Describe what starts, and when.

Once your initializer classes exist, register them in shared code. In this example, AnalyticsInitializer declares LoggerInitializer as a dependency, so the logger is created first.

commonMain / AppStartup.kt 
import io.github.kunal26das.startup.StartupManifest

/** The shared startup graph. */
val appStartup = StartupManifest {
    lazyInitializer<LoggerInitializer> { LoggerInitializer() }
    metaData<AnalyticsInitializer> { AnalyticsInitializer() }
}

Lazy components still start when an eager component needs them. On Android, declare eager initializers in XML too. On other platforms, call Startup.install from your entry point.

Android registration is explicit. The Kotlin manifest does not generate Android XML. Initializers need a public no-argument constructor.

Web startup is synchronous. Ordinary initializers work on JS and Wasm. The blocking CoroutineInitializer bridge is unsupported on these targets.
